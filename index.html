파트별 할 일과 담당자

배정 0 / 4

할 일 오른쪽의 "옮기기"를 고르면 다른 파트로 넘어가요. 난이도 칸이 주황이면 4~5칸(어려운 일)이에요.

난이도는 5칸 중 몇 칸이에요. 1~2칸은 수업 예제 그대로, 3칸은 예제를 고쳐 써야 하고, 4~5칸은 처음 해 보거나 수업에 없는 일이에요. 파트 난이도는 할 일 난이도의 평균이에요.

같이 상의할 문제

정하지 못한 것을 여기에 모았어요. 정해지면 지우거나 설계서에 옮겨요.

  1. 가상 공격(테스트 로그)을 어떻게 만들지 공격은 수업에서 배우지 않았어요. 탐지와 차단을 보여 주려면 로그인 실패 반복, 새벽 접근, OCC 접근 시도 기록이 필요해요. (가) 로그 파일을 손으로 몇십 줄 만들어 쓴다. (나) 1과목 Python 반복문으로 가짜 로그를 자동으로 만든다. 누가 맡을지도 같이 정해요.
  2. 초동 대응 리포트에 LLM을 쓸지 5과목 수업은 사고 개요와 후속 조치 문단만 LLM이 쓰고, 탐지 근거·조치 내역·현재 상태는 기존 데이터로 채워요. LLM 없이 템플릿만으로도 만들 수 있어요.

이 보기에서는 공유 저장을 쓸 수 없어요. 입력한 내용은 이 브라우저에만 남아요.

스키마

파트끼리 주고받는 것만 모았어요. 형식은 수업 슬라이드를 기준으로 하고 출처 슬라이드 번호를 적었어요. 수업에 없는 필드는 [추가]로 표시했어요. 예시 수정으로 같이 고칠 수 있고, 고친 내용은 모두에게 보여요. 수업 수업 그대로  수업+추가 수업 + 우리가 더한 필드  초안 수업에 없어서 우리가 정함

파트1·3 로그 남기기로그인·정책·방화벽 로그 → 파트2 탐지탐지 결과 → 파트4 대응 결정조치 요청 · 알림 요청 → 파트1·3 조치 실행조치 결과 → 파트4 → 파트2 오탐 확인오탐 기록

탐지 결과

파트2 → 파트4수업+추가수정됨detection_result.json

4과목에서 이벤트 하나에 탐지 결과·위험 점수·우선순위를 붙이던 형식이에요. 위험 점수 등급은 낮음(0~29) 주의(30~59) 높음(60~79) 심각(80~100)이고, 우선순위는 HIGH / MEDIUM / LOW예요. event_type 값 이름은 "정할 것"에 있어요.

출처: 4과목 Day3 슬라이드 7·14~16, Day5 슬라이드 8~12 / 5과목 Day2 슬라이드 31(reason)

필드뜻
event_id이벤트 번호
user대상 계정
event_type이벤트 유형 (예: ABNORMAL_LOGIN)
detections탐지 항목별 결과: unauthorized_access, saas_anomaly, ioc_match, chain_match (true / false)
risk_score0~100
risk_level낮음 / 주의 / 높음 / 심각
priorityHIGH / MEDIUM / LOW
asset대상 자산
asset_criticality자산 중요도
reason탐지 이유 (5과목 조치 요청에서도 씀)
src_ip[추가] 출발지 IP (IP 차단에 필요)
detected_at[추가] 탐지 시각 (로그 시각 기준)
