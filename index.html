파트별 할 일과 담당자

배정 0 / 4

할 일 오른쪽의 "옮기기"를 고르면 다른 파트로 넘어가요. 난이도 칸이 주황이면 4~5칸(어려운 일)이에요.

난이도는 5칸 중 몇 칸이에요. 1~2칸은 수업 예제 그대로, 3칸은 예제를 고쳐 써야 하고, 4~5칸은 처음 해 보거나 수업에 없는 일이에요. 파트 난이도는 할 일 난이도의 평균이에요.

같이 상의할 문제

정하지 못한 것을 여기에 모았어요. 정해지면 지우거나 설계서에 옮겨요.

  1. 가상 공격(테스트 로그)을 어떻게 만들지 공격은 수업에서 배우지 않았어요. 탐지와 차단을 보여 주려면 로그인 실패 반복, 새벽 접근, OCC 접근 시도 기록이 필요해요. (가) 로그 파일을 손으로 몇십 줄 만들어 쓴다. (나) 1과목 Python 반복문으로 가짜 로그를 자동으로 만든다. 누가 맡을지도 같이 정해요.
  2. 초동 대응 리포트에 LLM을 쓸지 5과목 수업은 사고 개요와 후속 조치 문단만 LLM이 쓰고, 탐지 근거·조치 내역·현재 상태는 기존 데이터로 채워요. LLM 없이 템플릿만으로도 만들 수 있어요.

이 보기에서는 공유 저장을 쓸 수 없어요. 입력한 내용은 이 브라우저에만 남아요.

스키마

파트끼리 주고받는 것만 모았어요. 한 파트 안에서만 쓰는 파일은 각자 정해요. 예시 수정으로 같이 고칠 수 있고, 고친 내용은 모두에게 보여요. 수업 수업에 나온 형식  초안 우리가 정한 형식

공통 로그 (한 줄 = 한 건)

파트1·3 → 파트2수업수정됨access.log

2과목 정책 로그 필드에 source와 reason을 더했어요. 파일은 한 줄에 JSON 하나(JSON Lines)로 저장해요. 2과목 수업은 result 대신 decision(ALLOW/DENY)을 쓰는데, 어느 쪽으로 통일할지는 "정할 것"에 있어요.

필드뜻
timestamp발생 시각 (ISO 8601)
source로그를 남긴 곳 (firewall / occ)
src_ip출발지 IP
dst_ip목적지 IP
user계정 (없으면 -)
role역할 (없으면 -)
resource접근 대상
action시도한 동작 (login / access / revoke)
result결과 (success / fail / deny)
reason실패·차단 사유 (없으면 -)
{
  "timestamp": "2026-11-02T02:14:05",
  "source": "firewall",
  "src_ip": "192.168.30.12",
  "dst_ip": "192.168.10.11",
  "user": "-",
  "role": "-",
  "resource": "occ/revoke",
  "action": "access",
  "result": "deny",
  "reason": "policy_default_deny"
}

탐지 결과

파트2 → 파트4초안수정됨detections.json

파트2가 만들고 파트4가 읽어요. 5과목 SOAR의 공통 이벤트 형식(event_type, priority, asset, impact_scope)을 합쳤어요. 합칠지는 "정할 것"에 있어요.

필드뜻
event_id이벤트 번호
detected_at탐지 시각
rule걸린 탐지 룰
event_type비정상 로그인 / 트래픽 급증 / 비인가 접근 / SaaS 이상 사용 / 악성 행위 징후
user, src_ip대상 계정, 출발지 IP
risk_score위험점수 (0~100)
priorityhigh / medium / low
asset대상 자산 (예: occ)
impact_scope영향 범위 (예: single_user)
evidence근거가 된 로그 시각 목록
{
  "event_id": "E-0001",
  "detected_at": "2026-11-02T02:15:00",
  "rule": "failed_login_5_in_10min",
  "event_type": "비정상 로그인",
  "user": "emp3",
  "src_ip": "192.168.30.12",
  "risk_score": 80,
  "priority": "high",
  "asset": "occ",
  "impact_scope": "single_user",
  "evidence": [
    "2026-11-02T02:10:11",
    "2026-11-02T02:14:05"
  ]
}

파트4가 만들고 파트1 계정 조치 또는 파트3 IP 차단이 읽어요.

필드뜻
event_id이벤트 번호
actionlock_account / unlock_account / terminate_session (파트1 실행), block_ip / unblock_ip (파트3 실행)

필드뜻
event_id이벤트 번호

필드뜻
event_id이벤트 번호
action, target실행한 조치와 대상

  "executed_at": "2026-11-02T02:15:05",
  "dry_run": false

timestamp조치 시각
event_id이벤트 번호
action, target조치와 대상
reason사유 (필수)
resultsuccess / fail
dry_run테스트 모드 여부

  "event_id": "E-0001",
  "action": "block_ip",
